# 08. Архитектура

Черновик от 2026-10-11, составлен до создания проекта. Основан на шаблоне Fabric для 26.3, документации Fabric и миксинах модов goldsqource (26.3) и Squake++ (1.19.4). Сам код Minecraft 26.3 ещё не прочитан, поэтому утверждения о поведении игры помечены **[подтвердить по коду]** и уточняются на шаге 3 плана.

## 1. Исходные данные

Из ветки `26.3` репозитория `FabricMC/fabric-example-mod` (прочитано 2026-10-11):

| Что | Значение |
|---|---|
| Minecraft | 26.3 |
| Fabric Loader | 0.19.5 |
| Fabric API | 0.162.0+26.3 |
| Loom | 1.18-SNAPSHOT, плагин `net.fabricmc.fabric-loom` |
| Gradle | 9.7.1 (через wrapper, отдельно не ставится) |
| Java | 25 |
| Наборы исходников | раздельные: `src/main` (общий код) и `src/client` (только клиент) |

Идентификатор мода `tf2mc`, пакет `io.github.egorka2000.tf2mc`.

## 2. Модули и зависимости

Три части, зависимости идут строго в одну сторону:

```
physics  ◄──  main  ◄──  client
(чистая Java)  (общий код мода)  (только клиент)
```

| Часть | Где лежит | От чего зависит | Что внутри |
|---|---|---|---|
| `physics` | отдельный подпроект Gradle `physics/` | только JDK | Математика движения и взрыва в единицах TF2 |
| `main` | `src/main` | `physics`, Minecraft, Fabric API | Mixin движения, классы, оружие, сущности, сеть, конфиг, команды |
| `client` | `src/client` | `main` | Ввод, HUD, рендер, приём пакетов |

`physics` вынесен в подпроект, а не в пакет внутри `main`, чтобы правило «без зависимостей от Minecraft» обеспечивала сборка: класс Minecraft там просто не скомпилируется. Побочный плюс: его тесты запускаются за секунды и не требуют загрузки игры.

Способ упаковки подпроекта в jar мода определяется в T1.1.

## 4. Граница единиц

- Внутри `physics` всё в единицах TF2: u, u/s, u/s², секунды.
- Minecraft хранит скорость в блоках за тик.
- Пересчёт делается в одном месте, в `movement/` (мост): `блоки/тик = u/s ÷ масштаб ÷ 20`.
- Масштаб (45 u/блок) берётся из конфига. Ни в `physics`, ни в остальном коде число 45 не встречается.

## 5. Движение

### Кто считает движение

В Minecraft движение своего игрока считает клиент и отправляет позицию серверу. Сервер игрока не пересчитывает, а только проверяет присланную позицию на правдоподобие **[подтвердить по коду]**.

Следствие для проекта: формулировка «один и тот же код на клиенте и сервере» означает не повторный расчёт на сервере, а три вещи:

1. Мод установлен на обеих сторонах, и серверные проверки не отбрасывают скорости TF2.
2. Параметры движения задаёт сервер и рассылает клиентам, клиент свои значения не использует.
3. Всё, что меняет скорость извне (взрыв), считает сервер и отправляет клиенту.

Сервер при этом доверяет клиенту в том, как тот движется. Защита от читов в scope не входит.

### Точка встраивания

Оба прочитанных мода перехватывают начало метода `travel` у игрока и отменяют ванильный расчёт, когда свой расчёт отработал. goldsqource собран под 26.3, поэтому имена подтверждены для нашей версии: `Player.travel(Vec3)`, `LivingEntity.aiStep()`, `LivingEntity.jumpFromGround()`, поле `LivingEntity.noJumpDelay`, `Entity.moveRelative(float, Vec3)`. Таблица — в `06-references.md`.

Берём тот же подход: Mixin в начало `Player.travel(Vec3)` с отменой ванильного расчёта.

Порядок внутри перехвата:

1. Проверить, применимо ли движение TF2. Если нет — ничего не делать, работает ваниль.
2. Собрать `MoveInput` и `MoveState`, пересчитать в единицы TF2.
3. Вызвать `SourceMovement` (один раз или по подшагам).
4. Пересчитать скорость обратно и передать её штатному методу перемещения игры, чтобы столкновения с блоками и подъём на ступеньки остались ванильными.
5. Отменить ванильные трение, ускорение и гравитацию.

Движение TF2 не применяется, и остаётся ваниль: в воде и лаве, на лестницах и лианах, при полёте на элитрах, в творческом полёте и режиме наблюдателя, верхом, а также если у игрока не выбран класс TF2.

### Прыжок

Высота прыжка задаётся параметром и подбирается под 50 u (см. `05-sources.md`). Перехват — в `LivingEntity.jumpFromGround()`.

Ванильная задержка между прыжками при удержании клавиши мешает распрыжке. goldsqource убирает её, обнуляя `noJumpDelay` в `aiStep()`. Открытый вопрос T1.3: в TF2 удержание прыжка не даёт прыгать непрерывно, на каждый прыжок нужно новое нажатие. Повторять ли это поведение или разрешить прыжок по удержанию, решается на прототипе.

### Подшаги

`SourceMovement` принимает шаг времени параметром, поэтому три подшага по 1/60 с и один шаг 0,05 с — это один и тот же код с разными аргументами. Открытый вопрос T1.4: проверять столкновения на каждом подшаге или один раз за тик.

## 6. Сеть

Fabric API: запись-пакет реализует `CustomPacketPayload`, регистрируется через `PayloadTypeRegistry`, отправляется через `ServerPlayNetworking` и `ClientPlayNetworking`.

| Пакет | Направление | Когда |
|---|---|---|
| Параметры движения и масштаб | сервер → клиент | при входе игрока и после перечитывания конфига |
| Класс игрока | сервер → клиенты | отдельный пакет не нужен, если класс хранится через Attachment API с синхронизацией (раздел 8) |
| Выстрел | клиент → сервер | при нажатии атаки; сервер проверяет боезапас и интервал |

Скорость от взрыва отдельного пакета не требует: сервер меняет скорость игрока и помечает её как изменённую, игра сама отправляет штатный пакет скорости **[подтвердить по коду]**.

Известный риск: ракетный прыжок в этой схеме срабатывает с задержкой на пинг, потому что импульс приходит с сервера. В TF2 клиент предсказывает свой взрыв. Для прототипа задержка принимается; предсказание на клиенте — возможная доработка после вехи.

## 7. Конфиг

- Один JSON-файл в папке конфигов игры: параметры движения, масштаб, число подшагов.
- Чтение через Gson, который уже входит в Minecraft; новая зависимость не нужна.
- На выделенном сервере действует файл сервера, клиент получает значения пакетом.
- Перечитывание командой `/tf2 reload`.

## 8. Классы TF2

- Описание класса (HP, скорость, набор оружия) — данные, а не код.
- Класс игрока хранится на сервере и должен переживать смерть и перезаход.
- Рекомендуемый способ хранения — Attachment API из Fabric API: `AttachmentRegistry.create` с `persistent(...)`, `copyOnDeath()` и `syncWith(..., AttachmentSyncPredicate.all())`. Это даёт сохранение, перенос через смерть и рассылку клиентам без своего пакета. Открытый вопрос 5, ждёт подтверждения перед шагом 8 плана.
- Максимальная скорость класса передаётся в `MoveParams`, а не через ванильный атрибут скорости, потому что ванильное ускорение отключено.

## 9. Данные

`classes.json` и `weapons.json` лежат в ресурсах мода, `src/main/resources/data/tf2mc/`. Игра грузит их как датапак и перечитывает командой `/reload`. Корневой папки `data/` в репозитории нет (решение от 2026-10-11).

Единицы TF2 (u, u/s) хранятся в файлах как есть, пересчёт в блоки делает код через масштаб из конфига. Каждое число сначала получает строку со статусом `сверено` в `05-sources.md`.

## 10. Ракета и взрыв

- Ракета — своя сущность-снаряд. Каждый тик сервер проверяет весь отрезок пути за тик (около 1,2 блока при 1100 u/s) на пересечение с блоками и сущностями.
- Взрыв свой: блоки не разрушает. Урон и отбрасывание считает `ExplosionMath` из `physics`, поэтому формулы покрываются юнит-тестами.
- Эффекты и звук — из ванильных ресурсов Minecraft. Ассеты Valve не используются.

## 11. Тесты

| Уровень | Где | Что проверяет | Состояние |
|---|---|---|---|
| Юнит-тесты мода | `src/test` | Согласованность `fabric.mod.json` с кодом: идентификатор, точки входа, конфиги миксинов. Все JSON-файлы в `src` разбираются | есть, 5 тестов |
| Юнит-тесты физики | `physics/src/test` | `SourceMovement`, `ExplosionMath`, без игры | появятся в T1.1 |
| Серверные игровые тесты | `src/gametest` | Сейчас: сервер с модом стартует. Позже: ракета, взрыв, смена класса | есть, дымовой тест |
| Клиентские игровые тесты | — | Запуск клиента с модом | не настроены, нужен виртуальный экран в CI |
| Ручная проверка | игра | Ощущения, связка «выделенный сервер + клиент» | по шагам плана |

Всё автоматическое запускается одной командой `gradlew build`. Только юнит-тесты: `gradlew test`. Только игровые: `gradlew runGameTest`.

Юнит-тесты написаны на обычном JUnit 5 и классы Minecraft не загружают. Если понадобится тестировать код, который трогает классы игры, потребуется `fabric-loader-junit` — это отдельная зависимость, подключается по согласованию.

### Линтеры и проверки кода

| Проверка | Что ловит | Где настроена |
|---|---|---|
| Предупреждения компилятора как ошибки | Сырые типы, небезопасные приведения, устаревшие вызовы и остальное из `-Xlint:all` | `build.gradle`, для всех наборов исходников |
| Checkstyle 14.3.0 | Неиспользуемые импорты и импорты со звёздочкой, пустые блоки, пропущенные скобки и `@Override`, отступы пробелами, пробелы в конце строк | `config/checkstyle/checkstyle.xml` |
| Проверка JSON | Битый JSON в ресурсах мода | тест `ResourceJsonTest` |
| `.editorconfig` | Единые отступы и кодировка в редакторе | корень репозитория |

Из `-Xlint:all` исключены две категории, которые сообщают не о коде мода: `processing` (шум от обработчиков аннотаций) и `classfile` (аннотации внутри чужих jar).

Запуск только проверок без сборки jar: `gradlew check`. Отчёты Checkstyle: `build/reports/checkstyle/`.

Форматирование автоматически не исправляется. Для VS Code нужно расширение «EditorConfig for VS Code», тогда отступы выставляются сами.

Чего нет и когда добавлять: статический анализ (SpotBugs или Error Prone) — когда появится логика движения; автоформатирование (Spotless) — если ручного соблюдения стиля станет недостаточно; клиентские игровые тесты — когда появится клиентская логика. Каждое из этих добавлений — новая зависимость, подключается по согласованию.

### CI

`.github/workflows/build.yml` запускается на каждый PR и на каждый коммит в `main`: ставит JDK 25, проверяет подлинность `gradle-wrapper.jar`, выполняет `gradlew build` — то есть все линтеры и тесты из таблиц выше. При падении сохраняет отчёты тестов и Checkstyle и логи тестового сервера, при успехе — собранный jar. Новый коммит в ту же ветку отменяет незаконченный прогон.

## 12. Среда

- VS Code: документация Fabric поддерживает его, но рекомендует IntelliJ IDEA. Для VS Code нужен набор расширений «Extension Pack for Java».
- Запуск из терминала работает в любом редакторе: `gradlew runClient`, `gradlew runServer`, `gradlew test`.

## 14. Решения и открытые вопросы

Приняты 2026-10-11 (записаны в журнал `04-decisions.md`): данные в ресурсах мода, JUnit 5 для тестов, сервер доверяет движению клиента.

Остаются открытыми:

1. Хранение класса через Attachment API — ждёт подтверждения перед шагом 8.
2. Прыжок по удержанию клавиши или по каждому нажатию — решается на прототипе в T1.3.
3. Столкновения на каждом подшаге или раз за тик — решается в T1.4.
4. Способ упаковки подпроекта `physics` в jar мода — решается в T1.1.
