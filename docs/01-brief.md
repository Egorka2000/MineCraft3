# 01. Бриф: TF2 в Minecraft

> Исправленная версия первого наброска. Числа с пометкой **[проверить]** надо сверить с TF2 Wiki до использования в коде.

## 1. Цель и scope

**Цель**: перенести в Minecraft классы TF2 со стоковым оружием.
**Желательно**: воспроизвести движение игрока из Source (не VPhysics).

**Вне scope**: пользовательские карты, кастомное оружие, режимы (Payload / CTF / Control Points), боты, матчмейкинг.

**Минимум для играбельности, который всё же нужен** (в первом наброске отсутствовал):
- команды RED/BLU и респавн;
- пополнение боезапаса и здоровья (аптечки, ящики или команда);
- решение «одиночная игра или мультиплеер» (см. `04-decisions.md`).

**Ассеты**: модели, звуки и текстуры Valve не использовать. Цифры и механики с вики использовать можно.

## 2. Ключевые ограничения

- Физика Source (VPhysics) не переносится. Переписываем только **движение игрока** (код класса движения Source, «QPhysics» в обиходе) на Minecraft через Mixin.
- Физика остаётся критическим путём: сначала прототип Soldier + ракетный прыжок на плоской карте, затем остальное.
- В Minecraft движение игрока считает клиент, сервер проверяет. Mixin должен давать одинаковый результат на обеих сторонах (см. `02-physics.md`).
- Тикрейт Minecraft 20 Гц, TF2 около 66 Гц. Это главный технический риск.

## 3. Таймлайн (одиночка, 10–15 ч/нед)

| Веха | Оценка |
|---|---|
| Прототип: движение + Soldier + ракетный прыжок | 1–2 месяца |
| Мини-версия (Soldier + Scout, одна тестовая карта) | 2–4 месяца |
| Играбельный мод (5 классов) | 8–12 месяцев |
| Все 9 классов со стоком | 12–18 месяцев и больше |

Для новичка в Java оценки скорее нижние. Заложить 2–3 недели на базовый Java до начала работы с Fabric.

## 5. Этапы

### Этап 0. Подготовка
Выбрать версию Minecraft и Fabric (см. `04-decisions.md`), создать проект из шаблона Fabric, убедиться, что пустой мод запускается.

### Этап 1. Движение (критический путь)
Подробно в `02-physics.md`. Критерий готовности: ракетный прыжок Soldier и распрыжка Scout ощущаются как в TF2.

### Этап 2. Каркас классов
- Хранение класса игрока (Attachment API Fabric или NBT, решение в `04-decisions.md`).
- Команда `/tf2 class <имя>`.
- Применение HP, скорости и экипировки при смене класса.

### Этап 3. Классы (порядок по сложности)
Soldier → Scout → Pyro → Heavy → Medic → Demoman → Sniper → Engineer → Spy.

Технические замечания, которых не было в первом наброске:
- **Ракета**: кастомный взрыв (своя формула отбрасывания и урона, без разрушения блоков). Ванильный `createExplosion` не подходит.
- **Быстрые снаряды**: ракета летит около 1100 u/s, это порядка блока за тик. Нужна проверка столкновений вдоль всего пути за тик.
- **Spy**: подмена скина и ника требует вмешательства в рендер игроков, это отдельная крупная задача.
- **Engineer**: постройки как сущности с собственным ИИ, отдельный объём работы.

### Этап 4. Таблица стокового оружия
JSON в `src/main/resources/data/tf2mc/`, по три слота на класс. Заполнять строго по вики, каждое число с источником.

### Этап 5. Сборка и настройка
HUD (класс, HP, боезапас), синхронизация, тюнинг ощущений.

## 6. Инструменты

Fabric, Java 17+ (версия зависит от выбранной версии Minecraft **[проверить]**), IntelliJ IDEA, Blockbench, GeckoLib для анимированных моделей, Claude Code для итераций по миксинам и формулам.

## 7. Подводные камни

| Проблема | Решение |
|---|---|
| Нет опыта в Java | Базовый курс 2–3 недели до Fabric |
| Клиент и сервер расходятся | Общий чистый класс движения, тот же код на обеих сторонах |
| 20 Гц вместо 66 Гц | Подшаги внутри тика, клиентская интерполяция |
| Движение «не как в TF2» | Тюнинг параметров по таблице из `02-physics.md` |
| Рендер моделей | `EntityRenderer` и GeckoLib |
| Баланс | Цифры только с вики |
| Мотивация | Маленькие победы: сначала одна ракета |
