## Что есть сейчас

- **Мод** `tf2mc` собирается, клиент и выделенный сервер запускаются.
- **Математика движения** в подпроекте `physics`: трение, разгон, стрейф в воздухе, прыжок, гравитация.
- **Класс Soldier:** команда `/tf2 class soldier [ник]` выдаёт класс — 200 HP и движение TF2 со скоростью 240 u/s; `/tf2 class vanilla` возвращает обычную игру. Класс сохраняется и переживает смерть. На земле действуют правила TF2: не быстрее максимума класса, назад 90%, один прыжок на нажатие. Спидометр — `/tf2 speed on`.
- **Правила класса:** урон от падения по формуле TF2, без сытости, ванильной регенерации и бега; оверхил с затуханием (до 150% при лечении, командой — больше); отладочная команда `/tf2 health set|add <число> [ник]`; вместо сердец — число HP.
- **Команды игроков:** `/tf2 team red|blu|spectator|random [ник]`; игроки одной команды не наносят друг другу урон, ники окрашены в цвет команды. Вошедший в мир игрок — нейтральный, пока не выберет команду; `/tf2 team` показывает составы.
- **Ракета Soldier:** ракетница выдаётся вместе с классом — обойма 4, запас 20, перезарядка по одной ракете. Снаряд 1100 u/s, взрыв без разрушения блоков, урон и отбрасывание по формулам TF2, ракетный прыжок. Звуки выстрела, заряжания и взрыва из расширительного пака; модели ракеты пока нет.
- **Настройки** в `config/tf2mc.json`, команды `/tf2 config` и `/tf2 reload`.
- **Проверки:** 148 юнит-тестов (54 на математику, 94 на мод), 11 серверных игровых тестов, клиентский игровой тест с замерами движения на ровной площадке и на неровностях в одиночной игре и на выделенном сервере, предупреждения компилятора как ошибки, Checkstyle, проверка состава jar. Всё это, включая клиентский тест и тесты на готовом jar, идёт в CI на каждый PR (`08-architecture.md`, раздел 11).
- **Репозиторий:** ветка `main` защищена, слияние только через PR с четырьмя зелёными проверками CI и свежей веткой.
- **Документы:** числа TF2 с источниками (`05-sources.md`), архитектура (`08-architecture.md`), журнал решений (`04-decisions.md`).

### Шаг 6. Подключение движения к игре (T1.3) ✅

Движение TF2 включается командой `/tf2 movement on` (временно, до появления классов) — на шаге 8а команду заменил выбор класса; с максимальной скоростью 300 u/s. Спидометр — `/tf2 speed on`. Настройки сервера рассылаются клиентам при входе и после `/tf2 reload`.

Сообщений «moved wrongly» и «moved too quickly» на сервере нет.

Что выяснилось по ходу:

- **Игра умножает ввод на 0,98.** Без поправки полное нажатие давало 294 u/s вместо 300. Поправка внесена.
- **Игрока на земле нужно прижимать вниз.** Без движения вниз игра не видит опоры и считает игрока висящим в воздухе. Добавлено прижатие, близкое к ванильной гравитации за тик.
- **Взгляд обновляется раз в тик.** Внутри тика все три подшага считаются с одним и тем же направлением взгляда, поэтому на стрейф подшаги сейчас почти не влияют: прибавка получается один раз за тик, а не три. Это главный вопрос шага 7.

Не проверено автоматически: ощущения от движения. Оценку владелец проекта даст позже (решение от 2026-10-12), работа до неё продолжается по задачам, которым оценка не нужна. Высота ступеньки осталась ванильной (0,6 блока).

### Выполненные шаги по аудиту

#### Шаг 6а. Аудит: связка физики с игрой под юнит-тестами (T1.5, замечание О1-А) ✅

Сейчас код, соединяющий расчёт движения с Minecraft, проверяется только клиентским игровым тестом, который в CI не работает. Поломка движения пройдёт все автоматические проверки.

1. Вынести цикл подшагов из `Tf2Travel` в отдельный класс. С игроком он работает через маленький интерфейс: скорость, перемещение, опора под ногами, направление взгляда.
2. В `Tf2Travel` оставить только реализацию этого интерфейса поверх игрока Minecraft.
3. Юнит-тесты с подставным игроком: прижатие к земле, чтение скорости после столкновения, поправка ввода на 0,98, прыжок только в первом подшаге, сход с края без накопленной скорости падения.
4. Поведение в игре не меняется: клиентский игровой тест даёт те же замеры, что до выноса.

Готово, когда: юнит-тесты цикла подшагов идут в `gradlew build` и в CI; замеры клиентского теста прежние.

Сделано (PR #18): цикл подшагов вынесен в `SubstepLoop`, с игроком он работает через интерфейс `MovingBody`; `Tf2Travel` оставляет за собой проверку применимости, приём прыжка и реализацию интерфейса поверх игрока Minecraft. Восемь юнит-тестов с подставным игроком (точка с полом, стеной и потолком) проверяют прижатие к земле, поправку ввода на 0,98, направление по взгляду, чтение скорости после столкновения со стеной, одинаковую скорость прыжка при одном и трёх подшагах, прыжок только на первом подшаге и сход с края без скорости прижатия. Каждый тест проверен на чувствительность: если убрать соответствующую строку цикла, он падает. Остаётся локальный прогон `gradlew runClientGameTest`: замеры должны совпасть с прежними.

#### Шаг 6б. Аудит: клиентский тест на ступеньках, стенах и воде (T1.6, замечание О3) ✅

#### Шаг 8а. Класс игрока (T2.1, T2.2) ✅

Появился первый класс — Soldier: 200 HP, 240 u/s. Движение TF2 теперь включается выбором класса, временная команда `/tf2 movement` убрана.

- **Скорость:** максимальная скорость берётся из класса. Клиент узнаёт о классе из данных игрока, отдельного пакета нет; пакет настроек больше не несёт признак «движение включено».

| Что измерено | Результат |
|---|---|
| Скорость Soldier | 5,333 блока/с, то есть 240 u/s |
| Максимум здоровья на клиенте с классом и без | 200 и 20 |
| Стрейф за один прыжок с разбега | 263 u/s |
| Скольжение вдоль стены под 45° | 238,5 u/s |

#### Шаг 8в. Команды игроков (T2.6) ✅

Добавлен по решению владельца проекта от 2026-10-12, перед ракетой: взрыв сразу сможет различать своих и чужих.

- **Хранение:** ванильные команды таблицы счёта `tf2mc_red` и `tf2mc_blu` с выключенным огнём по своим. Игра сама сохраняет их в мире, красит ники и не пропускает урон между своими — своего кода для запрета урона нет.
- **Команда** `/tf2 team red|blu|spectator|random [ник]`; `/tf2 team` показывает свою команду. Свою команду выбирает любой игрок, чужую назначает оператор.
- **`random`:** команда, где меньше игроков из тех, кто сейчас на сервере; при равенстве — жребий.
- **`spectator`:** выход из команды и ванильный режим наблюдателя. При выборе команды возвращается прежний режим игры — его хранит сама игра.
- **Нейтральная команда:** игрок, вошедший в мир без команды, становится нейтральным — серый ник, не ранит игроков и не получает урон от них. Выбрать её нельзя. Добавлена по решению владельца проекта.
- **Составы:** `/tf2 team` показывает свою команду и списки красных, синих и нейтральных.
- **Тесты:** пять юнит-тестов и серверный игровой тест с двумя игроками: нейтральные при входе и их защита, урон по чужим, отсутствие урона по своим, составы команд, `random`, права, наблюдатель и возврат режима.

Не проверено: цвет ников на экране и поведение на выделенном сервере с настоящими клиентами — автоматического теста на это нет.

Причина та же, что была с классом на шаге 8а: событие перерождения срабатывает раньше, чем игра переносит сохранённые данные на нового игрока. Боезапас больше не переносится через смерть — он всё равно выдаётся заново.

Не сделано и не сверено:

- Форма кривой урона между сверенными точками: в моде она линейная, вики называет её кубической без коэффициентов.
- Смещение точки вылета ракеты вправо: числа на вики нет, ракета вылетает из глаз.
- Клавиши перезарядки нет: она идёт сама. Прерывание перезарядки выстрелом — допущение.
- Своя текстура ракетницы, модель ракеты и звуки — шаг 11 и расширительный пак.
- Как стрельба и перезарядка ощущаются в игре, автоматически не проверяется.

### Шаг 11. Звуки из расширительного пака (T8.1, T8.2) ✅

Расширительный пак впервые работает в игре.

- **Имена звуков.** Мод играет три звука по своим именам: выстрел ракетницы, заряжание ракеты, взрыв. Какой файл за ними стоит, он не знает.
- **Заглушки.** Без пака за этими именами стоят ванильные звуки: запуск фейерверка, взвод арбалета, взрыв. Мод ссылается на ванильные звуковые события, своих звуковых файлов в jar нет.
- **Мод читает `.wav` сам.** Игра понимает только `.ogg`, а звуки TF2 лежат в несжатом `.wav`. Мод добавляет в загрузку звуков игры собственное чтение такого файла, поэтому перекодировать ничего не нужно.
- **Конвертер** `tools/expansion-pack/convert-pack.ps1` копирует нужные звуки из расширительного пака и собирает ресурс-пак Minecraft, который встаёт вместо заглушек. Нужен только PowerShell. С версии 0.9.0 конвертер переводит сразу все таблицы звуков TF2 и складывает в архив ZIP также модели и текстуры, поэтому пак собирается один раз на все версии мода.
- **Моно.** При чтении стереозвук сводится в моно, иначе игра играла бы его без учёта расстояния и направления.
- **Скрипты пака в репозитории.** `build-pack.ps1`, конвертер и `make-pack.bat` лежат в `tools/expansion-pack/`: в них нет файлов Valve. `make-pack.bat` запускает оба шага двойным щелчком, без ввода команд. Сам пак и собранный ресурс-пак по-прежнему вне репозитория, в «Документах».

Проверено в тестовом клиенте: без пака звуки мода ведут на ванильные файлы; с включённым паком — на `rocket_shoot`, `rocket_reload` и `explode` из пака, все пять файлов TF2 читаются и проигрываются без ошибок. Постоянно в клиентском тесте остались проверка заглушек и проверка чтения `.wav` на собственном тестовом звуке; проверка с настоящим паком разовая, потому что пака в репозитории нет.

Первая версия конвертера перекодировала звуки в `.ogg` через Blender. Владелец проекта попросил обойтись без него — так появилось чтение `.wav` в самом моде.

Найдено при проверке `make-pack.bat` и исправлено: после переноса в репозиторий `build-pack.ps1` по умолчанию складывал файлы TF2 в папку рядом с собой, то есть внутрь репозитория. Теперь он пишет в «Документы», а папки пака добавлены в `.gitignore` на случай чужих настроек.

Не сделано и не проверено:

- На слух звуки не проверялись: тест видит только, какой файл выбран. Громкость и дальность слышимости может понадобиться подобрать.
- Остальные звуки (шаги, боль, реплики, голосовые команды) добавляются вместе со своими механиками.
- Реплики и голосовые команды лежат в `.mp3`: мод их пока не читает, конвертер пропускает с предупреждением. Понадобится своё чтение `.mp3` или библиотека.
- Сжатые разновидности `.wav` не читаются; в паке таких единицы.
- Раздача пака с сервера при входе — задача T8.5.

### Шаг 12. Модели персонажей с анимацией (T8.4, T3.12) 🔶 продолжение — следующий

Поставлен вперёд блоков по решению владельца проекта от 2026-10-13: хочется скорее увидеть привычные модели и анимации.

1. **Библиотека скелетной анимации** — новая зависимость мода, разрешена владельцем проекта. Сначала выяснить, есть ли она для Minecraft 26.3.
2. **Модель игрока с классом** рисуется модом вместо ванильной, по своему имени ресурса. В jar — своя простая заглушка.
3. **Ресурс-пак** подменяет заглушку моделью и анимациями: конвертер переводит их из формата Source.
4. **Точные хитбоксы** по костям модели, в том числе зона головы (T3.12).

Самая большая часть работы по паку: разбор формата моделей Source и перевод скелета и анимаций. Делится на несколько PR.

**Часть 1 сделана (PR #39):**

- Библиотека анимации — GeckoLib 5.5.7 для Fabric 26.3. Нужна только клиенту и только для моделей: без неё мод работает, игрок рисуется обычной моделью.
- Игрок с классом рисуется моделью по имени `tf2mc:class/soldier`, если в ресурсах есть её файл. Анимации «стойка» и «бег» переключаются по движению.
- Своей модели персонажа в моде нет. Без модели в ресурс-паке игрок остаётся с обычной моделью Minecraft и своим скином.
- Пока нет моделей, класс виден в имени: «Ник (soldier)», ник в цвете команды. Предложение владельца проекта.
- Проверка: в ресурсах тестового мода лежит простая фигура из кубов; клиентский тест сверяет, что игрока с классом рисует отрисовщик мода, а ванильного — игра, и что отрисовка от третьего лица в стойке и беге проходит без ошибок.

Первый вариант показывал мою фигуру-заглушку всем игрокам без пака. Владелец проекта её забраковал: теперь она есть только в тестах.

**Осталось в этом шаге:**

Решение 2026-10-16 (`04-decisions.md`): отдельного конвертера не будет. GeckoLib рисует только модели из кубов с жёсткой привязкой вершин к одной кости, а модели TF2 — сетки из тысяч треугольников, где вершина плавно гнётся между тремя костями. Мод сам читает файлы моделей TF2 из пака и сам их рисует. Части:

1. ✅ Чтение моделей: подпроект `sourcemodel` (MDL, VVD, VTX). Модель Soldier читается: 86 костей, 9626 вершин, 8310 треугольников, 4 материала, 18 хитбоксов.
2. ✅ Текстуры: чтение VTF (DXT1, DXT3, DXT5 и несжатые форматы) и VMT, включая материалы-заплатки. Текстура Soldier 1024×512 читается.
3. ✅ Отрисовка модели игрока с классом в начальной позе: Soldier из пака вместо Стива, скин по команде (RED/BLU). Начальная поза моделей игроков TF2 хранится с осью y вверх и лицом к +z.
4. 🔶 Анимации из `*_animations.mdl`: стойка, бег со смешиванием по направлению, присед, ходьба в приседе, прыжок — готово (0.15.0). Осталось: наклон корпуса за взглядом (`body_pitch`, `body_yaw`), жесты выстрела и перезарядки, плавные переходы между анимациями, оружие в руках.
5. Хитбоксы по костям с зоной головы (T3.12): наборы хитбоксов уже читаются из MDL.
- Вид от первого лица: руки и оружие — после анимаций.

## Порядок работы

- Задача закрыта, когда выполнен её критерий из `03-tasks.md` и статус там сменён на `[x]`.
