## Что есть сейчас

- **Мод** `tf2mc` собирается, клиент и выделенный сервер запускаются.
- **Математика движения** в подпроекте `physics`: трение, разгон, стрейф в воздухе, прыжок, гравитация.
- **Движение в игре:** включается командой `/tf2 movement on`, скорость 300 u/s; спидометр `/tf2 speed on`. Без команды игрок двигается ванильно.

- **Проверки:** 66 юнит-тестов (28 на математику, 38 на мод), 3 серверных игровых теста, клиентский игровой тест с замерами движения в одиночной игре и на выделенном сервере, предупреждения компилятора как ошибки, Checkstyle, проверка состава jar. Замеры клиентского игрового теста, одинаковые в одиночной игре и на выделенном сервере:

| Что измерено | Результат | Ожидалось |
|---|---|---|
| Скорость ходьбы до включения | 4,317 блока/с | ванильные 4,317 |
| Скорость с движением TF2 | 6,667 блока/с, то есть 300 u/s | 300 u/s |
| Остановка после отпускания клавиш | полная меньше чем за секунду | трение |
| Высота прыжка | 1,159 блока, то есть 52,2 u | 52,2 u |
| Прыжок при гравитации 400 вместо 800 | 2,318 блока | вдвое выше |
| Скорость после одного прыжка со стрейфом | 315 u/s | выше 300 u/s |
| Расхождение позиции клиента и сервера | 0 | 0 |

Сообщений «moved wrongly» и «moved too quickly» на сервере нет.

Что выяснилось по ходу:

- **Игра умножает ввод на 0,98.** Без поправки полное нажатие давало 294 u/s вместо 300. Поправка внесена.
- **Игрока на земле нужно прижимать вниз.** Без движения вниз игра не видит опоры и считает игрока висящим в воздухе. Добавлено прижатие, близкое к ванильной гравитации за тик.
- **Взгляд обновляется раз в тик.** Внутри тика все три подшага считаются с одним и тем же направлением взгляда, поэтому на стрейф подшаги сейчас почти не влияют: прибавка получается один раз за тик, а не три. Это главный вопрос шага 7.

Не проверено автоматически: ощущения от движения. Оценку владелец проекта даст позже (решение от 2026-10-12), работа до неё продолжается по задачам, которым оценка не нужна. Высота ступеньки осталась ванильной (0,6 блока).

## Порядок работы

- Одна задача — одна ветка и один PR в `main`. После слияния ветка удаляется локально и на GitHub.
- После каждой крупной волны изменений: коммит, обновление документов и статуса, проверка CI, тестов и линтеров, уборка временных файлов (правила в `CLAUDE.md`).
- PR вливается только с зелёным CI.
- Задача закрыта, когда выполнен её критерий из `03-tasks.md` и статус там сменён на `[x]`.
- Число TF2 попадает в код только после строки со статусом `сверено` в `05-sources.md`.
- Всё, что касается движения, проверяется дважды: в одиночной игре и в связке «выделенный сервер + клиент».
