## Порядок работы

- Одна задача — одна ветка и один PR в `main`. Незакоммиченная работа между сессиями не остаётся.
- После слияния PR рабочая ветка удаляется локально и на GitHub, локальный `main` обновляется. Смерженные ветки не накапливаются.
- После каждой крупной волны изменений: коммит, обновление документов и статуса, уборка временных файлов (правила в `CLAUDE.md`).
- PR вливается только с зелёным CI.
- Задача закрыта, когда выполнен её критерий «Готово, когда» из `03-tasks.md` и статус там сменён на `[x]`.
- Число TF2 попадает в код только после строки со статусом `сверено` в `05-sources.md`.
- Всё, что касается движения, проверяется дважды: в одиночной игре и в связке «выделенный сервер + клиент».

## Шаги

### Шаг 1. Пустой мод (T0.2)

1. Идентификатор мода `tf2mc`, пакет `io.github.egorka2000.tf2mc` (подтверждено 2026-10-11).
2. Взять шаблон Fabric под Minecraft 26.3 (ветка `26.3` репозитория `fabric-example-mod`). Версии Loom и Gradle из шаблона записаны в `04-decisions.md`.
3. Положить файлы шаблона в корень репозитория рядом с `docs/`.
4. Проверить сборку и запуск: `gradlew build`, `gradlew runClient`, `gradlew runServer`.

Готово, когда: пустой мод собирается, клиент и выделенный сервер запускаются с модом.

### Шаг 2. Досверка чисел движения

Закрыть статусы `не сверено` в `05-sources.md`, без которых нельзя писать T1.1:

1. `sv_gravity`, `sv_accelerate`, `sv_airaccelerate`, `sv_friction`, `sv_stopspeed`.
2. Ограничение `wishspeed` в воздухе (30 u/s).
3. Базовая скорость 300 u/s и скорости классов в u/s.
4. Начальная скорость прыжка: разобрать расхождение 289 u/s против расчётных 283 u/s.
5. Подтвердить размеры халла, открыв страницу VDC вручную.

Готово, когда: у каждого параметра из раздела 4 `02-physics.md` есть источник или явная пометка, что число подбирается тюнингом.

### Шаг 3. Изучение референсов

Прочитать goldsqource (основной референс, собран под 26.3) и Squake++ (см. `06-references.md`) и записать в `06-references.md` ответы:

1. В какой метод движения игрока встроен Mixin.
2. Как решено клиентское предсказание.
3. Используются ли подшаги.

Затем прочитать код движения игрока в Minecraft 26.3 и закрыть пометки **[подтвердить по коду]** в `08-architecture.md`.

Код не копировать. Готово, когда: выбрана точка встраивания Mixin для T1.3 и записана в `04-decisions.md`, черновик архитектуры подтверждён или исправлен.

### Шаг 4. Чистый класс движения (T1.1)

1. Класс `SourceMovement` без зависимостей от Minecraft: трение, ускорение на земле, ускорение в воздухе с ограничением `wishspeed`. Все величины внутри в единицах TF2.
2. Юнит-тесты из раздела 7 `02-physics.md`: разгон до максимума класса, остановка трением, прирост скорости при стрейфе в воздухе, одинаковый выход при одинаковом входе.
3. Время разгона вычислить из параметров и зафиксировать в тесте.

Готово, когда: тесты проходят командой `gradlew test`.

### Шаг 5. Конфиг (T1.2)

Файл с параметрами движения, масштабом и числом подшагов. Чтение при старте и перечитывание командой.

Готово, когда: смена значения в файле меняет поведение без пересборки.

### Шаг 6. Mixin в движение игрока (T1.3)

1. Тонкий Mixin: собирает ввод и состояние, пересчитывает блоки в единицы TF2, вызывает `SourceMovement`, записывает скорость обратно.
2. Один и тот же код на клиенте и сервере.
3. Проверка на плоском мире в одиночной игре, затем на выделенном сервере.

Готово, когда: игрок разгоняется и стрейфит в воздухе, на сервере нет сообщений «moved wrongly».

Это самый рискованный шаг плана: здесь проявятся расхождения клиента и сервера.

### Шаг 7. Подшаги (T1.4)

Сравнить три подшага за тик с одним шагом 0,05 с на одинаковых сценариях (распрыжка, стрейф в воздухе). Выбранный вариант записать в `04-decisions.md`.

### Шаг 8. Минимальный каркас класса (T2.1, T2.2)

Хранение класса игрока, команда `/tf2 class soldier`, применение HP и максимальной скорости. Только то, что нужно Soldier; остальные классы и `classes.json` (T2.3) — после вехи.

Перед началом подтвердить рекомендацию по открытому вопросу 5: хранить класс через Attachment API (см. `04-decisions.md`).

### Шаг 9. Ракета и ракетный прыжок (T3.1, T3.2)

1. Досверить радиус взрыва, формулу отбрасывания и самоурон (`05-sources.md`).
2. Сущность-снаряд со скоростью 1100 u/s и проверкой столкновений вдоль всего пути за тик.
3. Свой взрыв без разрушения блоков: урон и отбрасывание по формуле.
4. Отправка скорости клиенту, проверка на выделенном сервере.

Готово, когда: ракетный прыжок на плоской карте даёт высоту и дальность, сопоставимые с TF2.
